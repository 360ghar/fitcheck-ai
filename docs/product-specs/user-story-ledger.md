# FitCheck AI user-story ledger

Last reviewed: 2026-07-31

This is the authoritative verification ledger for the stories in
[user-stories.md](./user-stories.md) plus code-derived platform stories. The
older document remains the product-intent catalogue; this ledger is the source
for implementation status and verification claims.

## Status vocabulary

| Status | Meaning |
|---|---|
| verified | Executable evidence covers the stated behavior at the listed boundary. This is not a claim of production-scale validation. |
| implemented-unverified | Code and route/file evidence exist, but the required client, API, or external-system verification is missing. |
| partial | Some acceptance criteria are implemented, but documented scope is incomplete or behavior has a known limitation. |
| absent | No implementation evidence was found in the repository. |
| disabled-by-default | Code exists, but the shipped default intentionally does not expose or activate the feature. |
| blocked | Verification cannot run in the current environment or requires an external operator/product action. |

No story is marked verified merely because a component, route, or unit test
exists. Evidence identifies implementation; Verification identifies executable
or external proof.
